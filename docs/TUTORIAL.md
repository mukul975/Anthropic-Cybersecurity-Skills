# Tutorial: Using and Extending the Anthropic Cybersecurity Skills Library

This tutorial walks you through what this repository is, how AI agents actually
use the skills inside it, how to install it, how to read and run a skill, and how
to author and validate a new skill of your own.

> ⚠️ **Authorized & lawful use only.** This library contains offensive and
> dual-use techniques intended for authorized penetration testing, security
> research, defense, and education. Only use them against systems you own or have
> explicit written permission to test. See [SECURITY.md](../SECURITY.md).

---

## 1. What this repository is

This is a library of **817 structured cybersecurity skills** spanning **29
security domains** (cloud, DFIR, malware analysis, threat hunting, red teaming,
OT/ICS, AI security, and more). It is **not** a collection of scripts, wordlists,
or exploit code.

Each skill is an *AI-native playbook*: a small, structured document that tells an
AI agent **when** to use a technique, **what** it needs first, **how** to execute
it step by step, and **how** to verify the result — the same decision-making a
senior analyst follows.

Every skill follows the open [agentskills.io](https://agentskills.io) standard and
is cross-mapped to **six industry frameworks**:

| Framework | Version | What it maps |
|---|---|---|
| MITRE ATT&CK | v19.1 | Adversary behaviors and TTPs |
| NIST CSF 2.0 | 2.0 | Organizational security posture |
| MITRE ATLAS | v5.4 | AI/ML adversarial threats |
| MITRE D3FEND | v1.3 | Defensive countermeasures |
| NIST AI RMF | 1.0 | AI risk management |
| MITRE F3 (Fight Fraud) | v1.1 | Cyber-enabled financial fraud TTPs |

## 4. How an AI agent uses these skills

The design principle is **progressive disclosure** — the agent never loads all
817 skills at once.

- **~30 tokens to scan** each skill (frontmatter only)
- **500–2,000 tokens to fully load** a skill (the complete workflow)

This lets an agent search the entire library in a single pass without blowing its
context window:

```
User prompt: "Analyze this memory dump for signs of credential theft"

Agent's internal process:
  1. Scans 817 skill frontmatters (~30 tokens each)
     → matches tags/description/domain, shortlists ~12 relevant skills
  2. Loads top 3 fully:
     • performing-memory-forensics-with-volatility3
     • hunting-for-credential-dumping-lsass
     • analyzing-windows-event-logs-for-credential-access
  3. Executes each skill's Workflow section step by step
  4. Validates results using the Verification section
     → maps findings to ATT&CK T1003 (Credential Dumping)
```

The `index.json` catalog exists precisely to power step 1 — it is a flat list of
every skill's `name`, `description`, `domain`, and `path`.

## 5. Anatomy of a skill

Open any skill's `SKILL.md`. It has two parts.

### 5.1 YAML frontmatter (discovery metadata)

```yaml
---
name: analyzing-network-traffic-of-malware      # kebab-case, 1–64 chars
description: 'Analyzes network traffic generated by malware ... Activates for
  requests involving malware network analysis, C2 traffic decoding, ...'
domain: cybersecurity                            # always "cybersecurity"
subdomain: malware-analysis                      # from the allowed list
tags: [malware, network-analysis, PCAP, Wireshark, C2-detection]
version: 1.0.0
author: mahipal
license: Apache-2.0
nist_csf: [DE.AE-02, RS.AN-03, ID.RA-01, DE.CM-01]
mitre_attack: [T1071.001, T1571, T1573, T1095]
---
```

The `description` is deliberately keyword-rich because it is what the agent
matches against a user's prompt. Framework fields (`mitre_attack`, `nist_csf`,
`atlas_techniques`, `d3fend_techniques`, `nist_ai_rmf`, `mitre_f3`) are what make
this library cross-framework.

### 5.2 Markdown body (the playbook)

A well-formed skill uses these sections in order:

```markdown
## When to Use        → trigger conditions + an explicit "Do not use for..."
## Prerequisites      → required tools, access, environment
## Workflow           → numbered steps with real, runnable commands
## Key Concepts        → a reference table
## Tools & Systems
## Common Scenarios
## Verification        → how to confirm success and map findings to a framework
```

For example, `analyzing-network-traffic-of-malware` walks from *Initial PCAP
Overview* (`capinfos`, `tshark -z io,phs`) → *DNS analysis* (DGA/tunnel
detection) → *HTTP/TLS C2* (JA3 fingerprints) → *beaconing detection* →
*Suricata signature generation* → *file extraction with Zeek*.

### 5.3 Supporting files

- `references/*.md` — deep procedure references, standards numbers, API notes
- `scripts/*.py` — real working helper scripts the agent can run
- `assets/*.md` — filled-in checklists and report templates

## 6. Walkthrough: running a skill by hand

Say you have a suspicious `malware.pcap`. Find and follow the matching skill.

**Step 1 — locate the skill.** Search the catalog:

```bash
grep -i "pcap\|network traffic" index.json
```

or browse `skills/` by name. You'll land on
`skills/analyzing-network-traffic-of-malware/`.

**Step 2 — check `When to Use` and `Prerequisites`.** Confirm the skill fits
(sandbox PCAP analysis, writing detection signatures) and install the tools it
lists (Wireshark/tshark, Zeek, Suricata, NetworkMiner, `scapy`/`dpkt`).

**Step 3 — execute the `Workflow` steps.** Start with the overview commands:

```bash
capinfos malware.pcap
tshark -r malware.pcap -q -z io,phs      # protocol hierarchy
tshark -r malware.pcap -q -z dns,tree    # DNS summary
```

Then continue through DNS, HTTP/TLS, beaconing, and signature generation exactly
as the skill lays out.

**Step 4 — verify.** Use the `Verification` section to confirm your IOCs and map
what you found to the relevant ATT&CK techniques (here, `T1071.001` for web-based
C2).

When an AI agent does this, it performs the same four steps automatically after
matching your prompt to the skill's frontmatter.

## 8. Authoring a new skill

### 8.1 Create the directory and `SKILL.md`

```bash
mkdir -p skills/your-skill-name
```

Add `skills/your-skill-name/SKILL.md` with valid frontmatter:

```yaml
---
name: your-skill-name
description: >-
  Clear description of what this skill does and when an AI agent should
  activate it. Include discovery keywords, tool names, and techniques.
domain: cybersecurity
subdomain: threat-hunting        # pick one from the allowed list
tags: [tag1, tag2, tag3]         # at least 2
version: "1.0"
author: your-github-username
license: Apache-2.0
---
```

Then write the body using the section order in §5.2 — real commands, real tool
names, explicit decision points, and an honest "Do not use for…" note.

### 8.2 Naming and quality rules

- Name is **kebab-case**, 1–64 characters, and matches the directory name.
- Description is **≥ 50 characters** and keyword-rich for agent discovery.
- `domain` is always `cybersecurity`.
- `subdomain` must be from the allowed list (see `CONTRIBUTING.md` or the
  validator's canonical list).
- `tags` is a list with **at least 2** items.
- Workflow steps use real, runnable commands — not summaries.

### 8.3 Optional supporting files

Add `references/standards.md` (CVE/NIST/MITRE references),
`references/workflows.md` (deep procedure), `scripts/process.py` (a working
helper), and/or `assets/template.md` (a filled-in checklist).

## 9. Validate before you submit

The repository ships a dependency-free validator (Python 3.8+, stdlib only) that
CI also runs, so it is the single source of truth for frontmatter rules.

```bash
# Validate one skill
python tools/validate-skill.py skills/your-skill-name/
```

```bash
# Validate the entire library
python tools/validate-skill.py --all
```

It checks that `SKILL.md` exists, the YAML frontmatter is well-formed, all
required fields are present (`name`, `description`, `domain`, `subdomain`,
`tags`, `version`, `author`, `license`), the name is valid kebab-case, the
description is long enough, the domain is `cybersecurity`, the subdomain is
allowed, and `tags` has ≥ 2 items.

Fix every error before opening a PR.
